# Simple Calendar Native App Requirements

## 1. 목표

Windows와 macOS에서 설치 또는 바로 실행 가능한 심플한 네이티브 달력 앱을 만든다.

앱은 한국어, 영어, 일본어, 중국어 UI를 지원해야 하며, 국가별로 다른 공휴일 정보는 공개 API를 통해 업데이트할 수 있어야 한다. 최종 산출물은 가능한 한 작고 단순해야 하며, 실행 파일 또는 배포 패키지 기준 10MB 이내를 목표로 한다.

## 2. 대상 플랫폼

- Windows
- macOS

## 3. 앱 형태

- 데스크톱 네이티브 앱
- Windows와 macOS 모두에서 동일한 코드베이스로 빌드 가능해야 함
- 설치형 또는 portable 실행 방식을 지원해야 함
- 사용자가 복잡한 런타임 설치 없이 바로 실행할 수 있어야 함

## 4. 핵심 기능

- 월간 달력 표시
- 이전 달 / 다음 달 이동
- 오늘 날짜로 이동
- 날짜 선택
- 선택한 날짜의 공휴일 표시
- 국가별 공휴일 업데이트
- 오프라인 상태에서도 최근에 받아온 공휴일 캐시를 사용할 수 있어야 함

## 5. 언어 지원

지원 UI 언어:

- 한국어
- 영어
- 일본어
- 중국어

언어별 기본 국가 매핑:

- 한국어: 대한민국
- 영어: 미국
- 일본어: 일본
- 중국어: 중국

사용자는 필요 시 언어와 공휴일 기준 국가를 별도로 선택할 수 있어야 한다.

## 6. 공휴일 데이터

- 국가별 공휴일은 공개 API를 활용해 업데이트한다.
- API 응답은 앱 내부에서 날짜 기준으로 정규화해 저장한다.
- 동일 날짜에 여러 공휴일이 있을 수 있으므로 복수 항목 표시를 지원해야 한다.
- API 장애 또는 네트워크 오류가 발생해도 앱이 종료되면 안 된다.
- 마지막 업데이트 시각과 업데이트 실패 상태를 사용자에게 표시해야 한다.

후보 API:

- Nager.Date 같은 공개 공휴일 API
- 국가별 공식 공공 데이터 API가 필요한 경우 확장 가능해야 함

## 7. 프레임워크 선정 요구사항

프레임워크는 다음 기준으로 선택한다.

- Windows와 macOS를 모두 지원
- 최종 산출물 크기를 10MB 이내로 유지하기 쉬움
- portable 실행 배포에 유리함
- 앱 UI가 단순한 달력 중심이므로 무거운 런타임을 포함하지 않음
- 자동 업데이트, 복잡한 백엔드, 대형 UI 프레임워크에 의존하지 않음

권장 방향:

- Tauri 2 기반 정적 HTML/CSS/JavaScript 앱
- OS 내장 WebView를 사용해 Electron보다 작은 산출물을 목표로 함
- Rust 쪽은 최소 앱 셸과 파일 저장 기능만 담당

피해야 할 방향:

- Electron 기반 앱: 크기 제한 10MB를 만족하기 어려움
- 대형 프론트엔드 번들러/컴포넌트 프레임워크 의존: 단순 달력 앱 요구에 비해 과함

## 8. 크기 및 배포 제약

- 최종 앱 산출물은 10MB 이내를 목표로 한다.
- 앱은 portable 방식으로 실행 가능해야 한다.
- 리소스 파일, 아이콘, 폰트, 라이브러리는 최소화한다.
- 시스템 폰트를 사용하고 별도 폰트 파일을 번들하지 않는다.
- 외부 이미지는 사용하지 않는다.
- 앱 기능에 필요하지 않은 빌드 산출물은 배포물에 포함하지 않는다.

## 9. UI 방향

- 심플한 달력 중심 화면
- 첫 화면에서 월간 달력과 오늘 날짜가 즉시 보여야 함
- 언어, 국가, 업데이트 상태는 작고 명확한 컨트롤로 제공
- 공휴일은 과한 장식 없이 날짜 셀 안에서 식별 가능해야 함
- Windows/macOS 모두에서 자연스럽게 보이는 시스템 UI 톤을 따른다.

## 10. 데이터 저장

저장 대상:

- 선택한 UI 언어
- 선택한 공휴일 국가
- 마지막으로 조회한 공휴일 데이터
- 마지막 업데이트 시각

저장 방식:

- 로컬 파일 또는 Tauri 앱 데이터 저장소 사용
- 민감 정보는 저장하지 않음
- 공휴일 API에 인증키가 필요한 경우 환경변수 또는 로컬 설정 파일로 분리

## 11. 비기능 요구사항

- 앱 시작이 빨라야 함
- 네트워크가 없어도 기본 달력 기능은 동작해야 함
- 공휴일 업데이트 실패가 전체 앱 사용을 막으면 안 됨
- 테스트 가능한 핵심 로직은 UI와 분리
- 날짜 계산은 타임존 차이로 하루가 밀리지 않도록 ISO 날짜 문자열 기준으로 처리

## 12. 검증 기준

완료 판정에는 다음 증거가 필요하다.

- Windows와 macOS용 빌드 경로가 문서화되어 있음
- macOS 빌드 산출물이 생성됨
- 가능하면 Windows portable 빌드 산출물 생성 또는 크로스 빌드 한계가 명확히 문서화됨
- 빌드 산출물 크기가 10MB 이내인지 확인됨
- 한국어, 영어, 일본어, 중국어 UI 전환이 동작함
- 국가별 공휴일 업데이트가 동작함
- 네트워크 실패 시 앱이 유지되고 캐시/오류 상태가 표시됨
- 핵심 날짜 계산 및 공휴일 정규화 테스트가 통과함

## 13. 현재 미정 또는 확인 필요 항목

- Windows 산출물을 macOS에서 직접 크로스 빌드할지, Windows 환경에서 별도 빌드할지
- 중국 공휴일 API 데이터의 신뢰성과 최신성
- 국가 선택 범위를 4개 기본 국가로 제한할지, API가 지원하는 전체 국가로 확장할지
- 최종 배포 형식을 단일 실행 파일 위주로 할지, 압축된 portable 폴더로 할지
